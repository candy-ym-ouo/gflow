# 07 · 前端界面设计

## 1. 定位与原则

- **简单前端**：纯静态页面（HTML + CSS + 原生 JavaScript），**无构建链、无框架依赖**（可选用 CDN 引入 Vue 3 的轻量用法，不作为硬性依赖），满足"搭配简单前端界面"的要求；
- **单二进制分发**：前端文件放 `web/`，由 `cmd/server/main.go` 通过 `//go:embed` 嵌入，`GET /ui/**` 提供访问；前端文件不计入 Go 行数/文件数约束；
- **数据来源**：全部经 REST API（docs/05），实时性靠 SSE 事件流；
- **只读+操作**：提供流程查看与审批操作，不做拖拽式设计器（JSON 编辑 + 校验即可）。

## 2. 页面结构

```
/ui
├── index.html            单页应用外壳（导航 + 内容区）
├── app.js                路由、API 封装、SSE 订阅、视图渲染
├── style.css             样式（深色侧边栏 + 内容区，响应式表格）
└── vendor/               （可选）本地化的第三方 JS（如 JSON 编辑器）
```

单页内按"视图"切换（hash 路由）：`#/dashboard`、`#/workflows`、`#/workflows/:id`、`#/instances`、`#/instances/:id`、`#/approvals`、`#/dead-letters`、`#/events`、`#/health`。

## 3. 视图设计

### 3.1 仪表盘（#/dashboard）

| 区块 | 内容 | 数据来源 |
| --- | --- | --- |
| 指标卡 | 运行中实例、待办审批、死信数、今日完成 | GET /metrics 解析 或 列表接口统计 |
| 最近事件 | 最近 20 条执行事件（实时滚动） | SSE 事件流 + GET /instances/{id}/events |
| 快捷操作 | 新建定义、启动实例、处理审批入口 | 链接 |

### 3.2 定义管理（#/workflows）

- 表格：名称、版本、状态（draft/published/archived）、更新时间、操作（查看/编辑/发布/归档/删除草稿）；
- **定义编辑器**：左侧 JSON 文本域（语法高亮/格式化），右侧实时校验结果面板（调用 `POST /workflows/validate`，逐条展示 path/code/message）；保存前必须校验通过；
- 支持从 `examples/` 导入示例定义（下拉选择填充）。

### 3.3 实例监控（#/instances、#/instances/:id）

- 列表：实例 id、流程名、bizKey、状态（彩色徽标）、当前节点、创建时间、操作（暂停/恢复/取消/重试/重启）；
- 详情页：
  - 状态时间线：按事件 seq 渲染（INSTANCE_STARTED → NODE_ENTERED → APPROVAL_* → … → COMPLETED），SSE 实时追加；
  - 节点面板：节点实例列表（状态、输入输出快照、attempts、lastError），失败节点红色标记；
  - 上下文查看：当前上下文 JSON（只读）；
  - 操作区：suspend/resume/cancel/retry/restart（按状态显示可用操作）。

### 3.4 审批中心（#/approvals）

- 我的待办：`GET /approval-tasks?assignee={当前用户}`，显示流程名、节点名、模式、截止时间（超时高亮）、意见输入框；
- 操作按钮：同意 / 驳回（必填意见） / 转办（输入目标用户）/ 加签 / 委派；
- 已办历史：审批记录列表（action/actor/opinion/时间）；
- 用户切换：顶部"当前用户"下拉（开发环境模拟多用户，配合 `X-User-Id` 头）。

### 3.5 死信与运维（#/dead-letters、#/health）

- 死信列表：失败原因、attempts、lastError、进入时间；操作：重试、重启、查看实例；
- 健康页：`GET /healthz` / `GET /readyz` 结果、store 状态、执行器状态、关键指标数字。

## 4. 前端交互流程

```
加载 → GET /healthz（失败显示离线提示）
     → 订阅 SSE /api/v1/events/stream（Last-Event-ID 续传）
     → 按 hash 路由渲染视图

审批操作流程（示例）：
  审批中心 → 点击"同意" → 弹窗填写意见 → POST /approval-tasks/{id}/approve
  → 成功：toast 提示，刷新待办列表，详情页时间线经 SSE 自动更新
  → 409/403：toast 错误（如"任务已处理"）

定义编辑流程：
  编辑 JSON → 点击"校验" → POST /workflows/validate → 面板展示 valid/errors
  → 校验通过 → 点击"保存" → POST /workflows → 跳转定义列表
```

## 5. API 对接映射（前端 → 后端）

| 视图 | 调用的接口 |
| --- | --- |
| 仪表盘 | GET /metrics、GET /instances、GET /approval-tasks、SSE |
| 定义列表/编辑 | GET /workflows、POST /workflows、PUT /workflows/{id}、POST /workflows/{id}/publish、POST /workflows/validate |
| 实例列表/详情 | GET /instances、GET /instances/{id}、GET /instances/{id}/nodes、GET /instances/{id}/events、POST suspend/resume/cancel/retry/restart |
| 审批中心 | GET /approval-tasks、GET /approval-tasks/{id}、POST approve/reject/transfer/add-approver/delegate/revoke、GET /instances/{id}/approval-records |
| 死信/运维 | GET /dead-letters、GET /healthz、GET /readyz、GET /metrics |

## 6. 实现要点

| 关注点 | 方案 |
| --- | --- |
| 实时刷新 | 全局单条 SSE 连接；事件到来按 instanceId 分发到当前视图 |
| 状态色 | 状态→颜色映射表（RUNNING 蓝、WAITING_* 橙、COMPLETED 绿、DEAD/FAILED 红、SUSPENDED 灰） |
| 时间显示 | 统一本地时间 + 相对时间（"3 分钟前"） |
| 错误提示 | 统一 toast + 响应 message 展示 |
| 无框架降级 | 全部原生 JS（fetch、事件监听、模板字符串渲染），无任何 npm 依赖 |
| 鉴权占位 | 顶部用户下拉 → localStorage 存 userId → 请求头 `X-User-Id` |

## 7. 验收要点（前端）

- 无需构建步骤：`go run ./cmd/server` 后直接访问 `/ui` 可用；
- 定义校验结果逐条可见，错误配置无法保存；
- 审批操作全流程（同意/驳回/转办）可用，事件流实时刷新；
- 死信实例可一键重试；
- 页面总数与 Go 源码无关，不占用行数/文件数约束。

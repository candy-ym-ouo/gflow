# 08 · 测试与运行校验

## 1. 测试策略

分层测试，覆盖从单元到端到端；**测试代码（`*_test.go`）不计入 Go 行数/文件数约束**。

| 层级 | 覆盖对象 | 示例场景 |
| --- | --- | --- |
| 单元测试 | condition、recovery、state、validator、dto、config | 表达式求值、退避计算、状态迁移合法性、校验规则、DTO 编解码 |
| 集成测试 | store（内存/SQL）、engine、approval、action | 全流程推进、会签判定、驳回路由、幂等去重、乐观锁冲突 |
| 端到端测试 | api + executor + store（内存） | HTTP 启动实例 → 审批 → 完成全链路；失败 → 重试 → 死信 → 人工 retry |

### 1.1 单元测试要点

- **condition**：比较/逻辑/正则/JSONPath/内置函数表驱动用例；键缺失、语法错误、求值异常降级策略；
- **recovery**：RetryPolicy 次数耗尽、fixed/exponential/linear 间隔计算、maxInterval 封顶、错误分类（可重试/不可重试）；
- **state**：实例与节点状态迁移全表驱动（合法迁移断言通过、非法迁移断言拒绝）；
- **validator**：每类校验规则的正反用例（悬空边、多开始节点、缺 default 边、非法动作类型、表达式语法、循环依赖检测）；
- **dto/config**：编解码往返一致、非法输入拒绝、默认值生效。

### 1.2 集成测试要点

- **engine 全流程**：start → condition 分支 → approval → action → end；并行/汇聚（parallel 扇出 + join 屏障）；驳回路由（previous/start/node/terminate）；
- **审批**：会签比例判定、或签、顺序审批逐人流转、转办/加签/委派/撤销、超时策略（autoApprove/autoReject/escalate）触发、终态操作冲突；
- **动作**：HTTP 动作（httptest 假服务）、幂等键去重（重复执行返回缓存结果）、失败重试写回 attempts；
- **store**：内存与 SQL 实现行为一致性（同一测试套件跑两种驱动）；乐观锁冲突返回 ErrConflict；扫描查询（ScanRunnable/ScanExpiring）过滤正确；
- **migrate**：空库迁移到最新版本、重复执行幂等、版本表记录正确。

### 1.3 端到端测试要点

- `POST /workflows`（含非法定义 → 400）→ `POST /workflows/{id}/instances` → 轮询 `GET /instances/{id}` 至 COMPLETED，断言事件序列完整；
- 审批链：创建会签任务 → 部分同意（未达比例仍等待）→ 全部同意 → 节点完成 → 下一节点推进；
- 失败恢复链：配置必然失败的动作（5xx）→ 断言重试次数与退避 → 耗尽进 DEAD → `POST /instances/{id}/retry` → 修改假服务为 200 → 实例完成；
- 幂等：同一实例并发触发推进（模拟多副本）→ 节点不重复执行、动作不重复调用；
- 迁移 + 重启续跑：启动 → 创建实例推进至一半 → 停止 → 换内存→SQL 或重启 → 断言从断点继续。

## 2. 运行校验（Runtime Validation）

### 2.1 定义校验（提交/发布时，validator.ValidateDefinition）

| 类别 | 规则 |
| --- | --- |
| 结构 | JSON 可解析；节点 id 唯一；有且仅有一个 start/end；边引用存在的节点（无悬空） |
| 图 | 无不可达节点；无环（条件/审批回路需经条件边显式跳出，校验器拒绝无条件环）；start 无入边、end 无出边 |
| 节点 | type 合法；approval 节点配置 mode/assignee(s) 合法；action 节点 kind 已注册、参数完整；wait 节点有 duration/until |
| 条件 | 每条非空 condition 可解析；condition 节点出边 ≥2 且有且仅有一条 default；同起点边 order 无冲突 |
| 恢复 | retry.maxAttempts ≥1、interval >0、backoff 合法；onFailure 值合法；补偿节点引用存在 |
| 上下文 | input/output 映射表达式语法合法（JSONPath/模板） |

校验失败 → `VALIDATION_FAILED`，错误按 path 逐条返回；**未通过校验的定义不允许发布与启动实例**。

### 2.2 运行校验（实例推进时，validator.ValidateRuntime）

| 场景 | 校验 |
| --- | --- |
| 启动实例 | 定义已发布；bizKey 非空；必填上下文键存在（若定义声明 required） |
| 推进节点 | 节点实例状态合法；输入映射取到的值类型匹配动作参数声明（可配置严格/宽松） |
| 审批操作 | 操作人是任务参与者（或管理员）；任务非终态；驳回路由目标节点存在 |
| 恢复 | 重试目标节点存在；补偿动作可用 |

运行校验失败按场景处理：参数类 → 不可重试错误（走失败/死信）；状态类 → 返回 CONFLICT 且不落脏状态。

### 2.3 启动自检（main 启动时）

```
1. 配置加载与校验（非法配置 fail-fast）
2. migrate.Run（autoMigrate=true 时）
3. store 可达性检查（ping）
4. 注册表自检：内置动作/条件函数/审批模式均已注册
5. 示例定义冒烟：加载 examples/leave.json → ValidateDefinition 必须通过
全部通过 → 打印 ready 日志并启动 HTTP/执行器；任一失败 → 退出非零
```

### 2.4 运行期健康检查

- `GET /healthz`：存活（进程 + 主循环 tick）；
- `GET /readyz`：store ping、migrate 版本一致、执行器运行中（上次调度轮在 N 秒内）；
- 健康检查失败影响：调度器降级重试，连续失败 N 次记录事件并置 readiness=0，负载均衡摘流量。

## 3. 校验器与引擎的接口关系

- `validator.ValidateDefinition(def) error`：纯函数，无副作用，api 层调用；
- `validator.ValidateRuntime(inst, node, params) error`：engine 推进前调用（可配置开关 `validator.runtime=true`）；
- validator 依赖 condition（表达式解析）与 action（动作注册表）以复用解析能力，避免重复实现。

## 4. 测试文件规划（不计入约束）

| 文件 | 覆盖 |
| --- | --- |
| internal/condition/evaluator_test.go | 表达式/函数/降级 |
| internal/recovery/retry_test.go、recover_test.go | 退避/分类/死信判定/补偿 |
| internal/engine/engine_test.go、transition_test.go、state_test.go | 全流程/并行汇聚/状态迁移表 |
| internal/approval/manager_test.go | 模式/操作/驳回/超时 |
| internal/action/executor_test.go | 动作执行/幂等 |
| internal/validator/validator_test.go | 定义/运行校验规则 |
| internal/store/memory_test.go、sql_test.go | 存储语义与一致性 |
| internal/migrate/migrate_test.go | 迁移幂等 |
| internal/api/*_test.go | handler 端到端 |

## 5. 覆盖率目标

- 核心逻辑（engine/condition/recovery/approval）语句覆盖率 ≥ 80%；
- 其余模块 ≥ 60%；
- CI 中 `go test ./... -coverprofile` 输出覆盖率报告，不达标告警。

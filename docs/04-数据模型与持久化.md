# 04 · 数据模型与持久化（含迁移）

## 1. 持久化目标

- **一切关键状态可落库**：定义、实例、节点实例、审批任务、审批记录、执行事件；
- **重启不丢进度**：任何时刻进程崩溃，实例都能从持久化状态恢复推进（断点续跑）；
- **多实现**：`store` 为接口，提供内存（开发/测试）与 SQL（生产）两种实现，语义一致；
- **版本化演进**：Schema 变更走迁移，幂等、可重复执行。

## 2. 领域实体与表设计

> 以下字段为逻辑设计；SQL 具体 DDL 由 `internal/migrate` 的嵌入式迁移文件提供（`migrations/*.sql`，不计入 Go 行数约束）。

### 2.1 workflow_definition（工作流定义）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | string | 定义 id（如 `leave-approval`） |
| name | string | 展示名称 |
| version | int | 版本号（同 id 下自增） |
| graph | text(JSON) | 节点与边（`WorkflowDefinition` 序列化） |
| status | enum | `draft / published / archived` |
| recovery_config | text(JSON) | 定义级恢复配置（实例最大重试、死信开关） |
| created_at / updated_at | datetime | 时间戳 |
| created_by | string | 创建人（鉴权占位） |

约束：`(id, version)` 唯一；`status=published` 的版本被实例引用后**不可修改**（可新建版本），保证实例与定义的一致性。

### 2.2 workflow_instance（工作流实例）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | string | 实例 id（UUID） |
| workflow_id | string | 定义 id |
| workflow_version | int | 使用的定义版本（快照引用） |
| biz_key | string | 业务键（如单据号），`(workflow_id, biz_key)` 可做幂等去重 |
| status | enum | 见 docs/02 §7.1（PENDING…TERMINATED） |
| context | text(JSON) | 实例上下文快照（最新合并结果） |
| current_node_ids | text(JSON) | 当前激活节点 id 集合（并行场景多个） |
| version | int | **乐观锁版本号**，每次推进 +1 |
| lease_owner / lease_expire_at | string/datetime | 执行器租约（多副本互斥） |
| next_retry_at | datetime | 最近重试/恢复时间（调度扫描依据） |
| error_info | text(JSON) | 最后错误信息 |
| created_at / updated_at / completed_at | datetime | 时间戳 |

索引：`status`、`next_retry_at`、`(workflow_id, biz_key)`、`updated_at`。

## 3. 序列化与上下文

- **上下文**：实例上下文是 `map[string]any`，以 JSON 存储；每次节点完成后**增量合并**（输出写回），全量快照落库；
- **定义图**：`WorkflowDefinition` 整体 JSON 序列化存入 `graph` 字段；加载时反序列化 + 校验（validator）；
- **时间**：统一 UTC 存储，展示层转本地；
- **版本化实例上下文**：上下文快照随实例 version 更新，为后续"回放/对比"留扩展空间（本期不实现回放）。

## 4. Store 接口（契约摘要）

```
Store:
  // 定义
  SaveWorkflowDefinition(def) / GetWorkflowDefinition(id, version) / ListWorkflowDefinitions(filter)
  PublishWorkflow(id) / ArchiveWorkflow(id)
  // 实例
  CreateInstance(inst) / GetInstance(id) / UpdateInstance(inst, expectedVersion)   // 乐观锁
  ListInstances(filter) / ScanRunnable(batch, now) / ScanExpiring(now)             // 执行器扫描
  // 节点实例
  SaveNodeInstance / GetNodeInstance(instID, nodeID) / ListNodeInstances(instID)
  // 审批
  SaveApprovalTask / GetApprovalTask(id) / ListApprovalTasks(assignee, status) / SaveApprovalRecord
  // 事件
  AppendEvent(ev) / ListEvents(instanceID, cursor, limit) / SubscribeEvents() (chan, cancel)
  // 迁移
  Migrate() error
```

- `UpdateInstance` 校验 `expectedVersion`，版本不符返回 `ErrConflict`，由 engine/executor 重读重算；
- `SubscribeEvents` 返回订阅通道：`api`（SSE）与测试均可订阅，内存实现为内存广播，SQL 实现为轮询增量（按 seq）或依赖驱动通知（本期用轮询，周期与调度器一致）。

## 5. 存储实现

### 5.1 内存实现（store/memory.go）

- 全部实体存于 `sync.RWMutex` 保护的 map；事件订阅为内存广播 channel；
- 语义与 SQL 实现一致（含乐观锁、扫描过滤），用于开发/测试/单机演示；
- 明确限制：进程重启即丢失，仅限非生产。

### 5.2 SQL 实现（store/sql.go）

- 支持 SQLite（默认，零依赖）与 PostgreSQL（可插拔，通过标准 `database/sql` + driver）；
- 所有写操作走事务；实例推进读-算-写在同一事务内完成（配合乐观锁）；
- 扫描查询走索引（status、next_retry_at、deadline）；
- 语句集中管理（常量表），便于审阅与换库。

## 6. Schema 迁移（internal/migrate）

### 6.1 设计

- **版本化**：`schema_migrations` 表记录已应用版本；
- **嵌入式**：迁移 SQL 文件（`migrations/0001_init.sql`、`0002_*.sql` …）通过 `//go:embed` 嵌入二进制，随发布分发；
- **幂等**：每个迁移文件内部语句可重复执行安全（`CREATE TABLE IF NOT EXISTS` 等）；
- **顺序执行**：按文件名版本号升序，仅执行 `version > max(applied)` 的迁移，每个迁移在一个事务内完成；
- **启动自动迁移**：`config.store.autoMigrate=true`（默认）时服务启动执行；可关闭由运维手动执行；
- **失败处理**：迁移失败即启动失败（fail-fast），不进入半初始化状态。

### 6.2 迁移文件清单（规划）

| 版本 | 文件 | 内容 |
| --- | --- | --- |
| 0001 | 0001_init.sql | 7 张基础表 + 索引（定义/实例/节点/审批/事件/迁移） |
| 0002 | 0002_instance_index.sql | 实例扫描索引（status, next_retry_at 联合） |
| 0003 | 0003_approval_index.sql | 审批任务待办/超时索引 |
| 0004 | 0004_event_seq.sql | 事件 seq 唯一约束与查询索引 |

### 6.3 数据兼容性

- 定义以 `(id, version)` 演进：已发布版本冻结，修改即升版本，实例引用版本快照；
- 实例上下文向后兼容：新增键不影响旧实例；读取缺失键按 `null` 处理；
- 迁移只做加表/加列/加索引（forward-only），回滚采用"新版本修正"策略而非 DDL 回滚。

## 7. 一致性保障

| 场景 | 机制 |
| --- | --- |
| 实例并发推进 | 乐观锁 version + 事务 |
| 多副本执行 | 租约（lease_owner/lease_expire_at）互斥 |
| 审批并发操作 | 任务行锁 + 状态机校验（终态不可再操作） |
| 事件顺序 | seq 单调分配（SQL 实现用序列/自增） |
| 幂等动作 | (instance_id, node_id, idempotency_key) 唯一约束 |
| 重启续跑 | 状态全量落库 + 调度器按 next_retry_at 扫描 |

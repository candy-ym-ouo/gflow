# 06 · 后台执行器与失败恢复

## 1. 设计目标

- **异步推进**：实例创建后不阻塞 API 请求，由执行器在后台调度推进；
- **可靠**：推进状态全量持久化，崩溃/重启后自动续跑；
- **多副本安全**：租约互斥，同一实例同一时刻只有一个副本推进；
- **幂等**：节点执行、动作副作用可重放；
- **可控**：批次、并发、租约时长均可配置；优雅停机不丢任务；
- **可观测**：每次推进/重试/死信均产生事件与指标。

## 2. 组件结构

```
executor/
├── scheduler.go     # 调度循环：扫描 → 分配 → 推进；租约管理；超时扫描
└── worker.go        # Worker 池：执行引擎 Advance、结果处理、重试入队
```

## 3. 调度循环（scheduler）

每 `schedulerInterval`（默认 1s）执行一轮：

```
1. 清理过期租约（lease_expire_at < now 的实例租约置空，供重新认领）
2. 超时扫描：审批任务 deadline 到期 → 触发 timeoutPolicy
             节点 next_retry_at 到期 → 进入可推进集
3. 扫描可推进实例（ScanRunnable）：
     状态 ∈ {PENDING, RUNNING, WAITING_ACTION, WAITING_RETRY(已到期)} 且
     未被租约占用或租约已过期，最多 scanBatchSize 个
4. 对每个实例尝试认领租约（CAS：lease_owner=本副本, lease_expire_at=now+leaseDuration）
     认领成功 → 投递给 Worker 池执行
5. 心跳：后台 goroutine 每 leaseRenewInterval 续租本副本持有的租约
```

**批次与节流**：`scanBatchSize` 限制单轮推进量；Worker 忙时实例在池中排队，租约在排队期间持续续租（防止超时被其他副本抢走）。

## 4. 节点执行（worker）

```
worker 收到实例：
  inst = store.GetInstance(id)                    # 读取最新
  for currentNode in inst.currentNodeIds:
      nodeInst = store.GetNodeInstance(inst, node)
      if nodeInst 已在执行/完成（幂等检查）: continue
      err = engine.Advance(inst, node)            # 引擎执行节点（含条件/审批/动作）
      switch err:
        nil → 节点完成，写回上下文，沿边推进下一节点，实例版本+1
        ErrRetryable → recovery.RetryPolicy 计算下次时间
                       → 节点 WAITING_RETRY / 实例 WAITING_RETRY（next_retry_at）
        ErrFatal     → 按 onFailure：fail → 死信判定；skip → 标记 SKIPPED 继续
  store.UpdateInstance(inst, version)             # 乐观锁提交
  冲突(ErrConflict) → 丢弃本轮，下轮重读（其他副本已推进）
```

**执行互斥**：同一实例的节点按序执行；并行分支（parallel）下 `currentNodeIds` 含多个节点，Worker 内顺序执行（可扩展为实例内并发，本期顺序保证一致性优先）。

## 5. 租约（Lease）

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| leaseDuration | 30s | 认领后独占时长 |
| leaseRenewInterval | 5s | 心跳续租周期 |

- 认领/续租均为 CAS 更新（`lease_owner, lease_expire_at`），天然支持多副本；
- 副本崩溃：租约到期后其他副本可重新认领，节点状态已持久化，继续推进（断点续跑）；
- 副本假死（网络分区）：租约过期后可能被其他副本接管，由于节点执行幂等（idempotency_key 去重），不会重复副作用。

## 6. 超时扫描

| 扫描项 | 判定 | 处理 |
| --- | --- | --- |
| 审批任务 | `deadline < now 且 status=PENDING` | 按 `timeoutPolicy`：remind（重发提醒+续期）/ autoApprove / autoReject / escalate / fail |
| 节点重试 | `next_retry_at <= now 且 status=WAITING_RETRY` | 重新入队推进 |
| 实例级 | `next_retry_at <= now` | 同上（实例级恢复） |

扫描同样需要租约保护（对任务/实例加锁），避免多副本重复触发（如 autoApprove 重复执行——由审批任务状态机终态校验兜底）。

## 7. 失败恢复流程（recovery 模块）

### 7.1 节点失败处理

```
节点执行返回错误 err：
  1. recovery.Classify(err) → retryable / fatal
  2. retryable 且 attempts < maxAttempts：
       间隔 = backoff(attempts, interval, maxInterval)
       节点 → WAITING_RETRY(nextRetryAt = now+间隔)；实例 → WAITING_RETRY
       事件 RETRY_SCHEDULED；指标 retries_total++
  3. 否则：
       按节点 onFailure：
         fail       → 节点 FAILED
                      recovery 判定实例：deadLetter? → DEAD : FAILED
                      事件 DEAD_LETTERED / INSTANCE_FAILED
         skip       → 节点 SKIPPED，沿 default 边继续（需定义允许）
         compensate → 逆序执行已完成节点的补偿动作，然后实例 FAILED
         toApproval → 生成人工干预审批任务（管理员处理）
```

### 7.2 人工干预

| 操作 | 触发 | 效果 |
| --- | --- | --- |
| retry | API `POST /instances/{id}/retry` | DEAD/FAILED → RUNNING，失败节点重置 attempts 重新执行 |
| restart | API `POST /instances/{id}/restart` | 从 start 节点重建节点实例重跑（原历史保留） |
| cancel | API `POST /instances/{id}/cancel` | 逆序补偿已完成节点 → TERMINATED |
| suspend/resume | API | 暂停/恢复推进（暂停中不参与扫描） |

### 7.3 补偿编排

- 节点 `compensation` 声明逆向动作（如"撤销部署"），与正向动作共用幂等键体系（`comp-${idempotencyKey}`）；
- 触发时按节点完成时间**逆序**执行；
- 补偿失败：进入重试（若可重试）或记录补偿失败事件并标记实例为 `FAILED(compensation_failed)`，由管理员处理。

## 8. 幂等保障清单

| 层面 | 机制 |
| --- | --- |
| 节点执行 | 节点实例状态机：RUNNING/SUCCEEDED 不重复执行；执行前检查 |
| 动作副作用 | `(instance_id, node_id, idempotency_key)` 唯一约束 + 结果复用 |
| 审批操作 | 任务状态机终态校验（终态操作返回 CONFLICT） |
| 调度推进 | 乐观锁 version + 租约 CAS |
| 补偿 | 独立幂等键 + 事件记录 |

## 9. 优雅停机

```
收到 SIGTERM/SIGINT：
  1. 停止调度器（不再认领新实例/新任务）
  2. 等待在途 Worker 完成当前节点执行（带超时，默认 30s）
  3. 释放本副本持有的全部租约（置 lease_expire_at = now，立即失效）
  4. 关闭事件订阅通道，停止 HTTP（等存量请求完成）
  5. 退出（0）
```

释放租约后，其他副本或本副本重启后的调度器可立即接管，不依赖租约自然过期。

## 10. 指标（metrics，Prometheus 格式）

| 指标 | 类型 | 说明 |
| --- | --- | --- |
| gflow_instances_total{status} | gauge | 各状态实例数 |
| gflow_instances_started_total | counter | 累计启动实例数 |
| gflow_instances_completed_total | counter | 累计完成数 |
| gflow_node_executions_total{type,result} | counter | 节点执行结果（success/fail/retry） |
| gflow_retries_total | counter | 重试次数 |
| gflow_dead_letters_total | counter | 死信数 |
| gflow_approval_tasks_pending | gauge | 待办审批数 |
| gflow_advance_duration_seconds{result} | histogram | 单次推进耗时 |
| gflow_scheduler_round_duration_seconds | histogram | 调度轮耗时 |
| gflow_lease_conflicts_total | counter | 租约冲突次数 |

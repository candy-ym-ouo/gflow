# 09 · 验收标准与开发计划

## 1. 验收标准

### 1.1 功能验收

| 编号 | 验收项 | 通过标准 |
| --- | --- | --- |
| F-1 | 工作流定义 | JSON 定义含节点/边/条件/审批/动作/恢复策略，可创建、更新、发布、归档、按版本查询 |
| F-2 | 节点能力 | start/end/approval/action/condition/parallel/join/wait 8 种类型全部可执行 |
| F-3 | 条件引擎 | 比较/逻辑/正则/JSONPath/内置函数表达式正确求值；条件节点按序路由并有 default 兜底 |
| F-4 | 审批中心 | 单人/会签/或签/顺序 4 模式；同意/驳回/转办/加签/委派/撤销 6 操作；驳回路由 4 策略 |
| F-5 | 自动动作 | HTTP/通知/等待/函数 4 类动作；输入输出映射；幂等键去重（重复执行不产生重复副作用） |
| F-6 | 失败恢复 | 错误分类、重试（fixed/exponential/linear）、超时策略、死信、人工 retry/restart、补偿、断点续跑 |
| F-7 | 实例持久化 | 实例/节点/审批/事件全量落库；进程重启后未完成实例自动续跑 |
| F-8 | Schema 迁移 | 空库一键迁移到最新；重复执行幂等；版本表正确 |
| F-9 | REST API | docs/05 全部端点可用、错误码语义正确；SSE 事件流实时推送且可续传 |
| F-10 | 后台执行器 | 调度/租约/Worker 正常；多副本不重复推进（并发测试通过）；优雅停机不丢任务 |
| F-11 | 运行校验 | 非法定义提交被拦截并返回逐条错误；启动自检通过才提供服务；/healthz、/readyz 正确 |
| F-12 | 前端 | `/ui` 免构建可访问；仪表盘/定义编辑校验/实例监控/审批中心/死信运维 可用；事件实时刷新 |
| F-13 | 测试 | `go test ./...` 全绿；核心模块覆盖率 ≥80%；含失败恢复与多副本幂等端到端用例 |

### 1.2 工程约束验收（硬性）

| 编号 | 约束 | 校验命令 | 通过标准 |
| --- | --- | --- | --- |
| E-1 | Go 行数（不含测试）>2000 且 <2200 | `find . -name '*.go' ! -name '*_test.go' -print0 \| xargs -0 wc -l \| tail -1` | 总行数落在 (2000, 2200) |
| E-2 | Go 源码文件数 >20 且 <25 | `find . -name '*.go' ! -name '*_test.go' \| wc -l` | 文件数落在 (20, 25) |
| E-3 | 禁止单文件实现 | `git grep -l 'package main' -- '*.go'` 仅 cmd/server/main.go | 分层模块与 docs/03 清单一致 |
| E-4 | 无循环依赖 | `go list ./... && go vet ./...` | 编译与 vet 通过 |
| E-5 | 前端不计入约束 | 统计时排除 web/ 与 migrations/ | 计数口径一致（E-1/E-2 基于 Go 源码） |

> 口径说明：统计仅针对 `*.go` 且排除 `*_test.go`；`web/`（HTML/JS/CSS）与 `migrations/`（SQL）不计入。规划目标 24 文件 / ≈2190 行，已落在双约束内并留有约 10 行安全余量（下限 2000 / 上限 2200）。

### 1.3 质量验收

- `go vet ./...`、`gofmt -l .` 无输出；
- 无 `context` 泄漏、无未处理错误（gosec/errcheck 建议项）；
- 关键路径均有事件与指标覆盖；README 快速开始四步可完整走通。

## 2. 开发计划（里程碑）

| 里程碑 | 内容 | 产出 | 关联文件 |
| --- | --- | --- | --- |
| M1 模型与校验 | 领域模型、配置加载、定义校验器、启动自检 | 可加载并校验定义 | model×3、config、validator、condition(evaluator 基础) |
| M2 存储与迁移 | Store 接口、内存/SQL 实现、迁移运行器、事件订阅 | 定义/实例可持久化，迁移幂等 | store×3、migrate |
| M3 引擎与审批 | 状态机、流转/条件路由/并行汇聚、审批任务与操作、重试/死信 | 单进程内可完整跑通请假流程（测试驱动） | engine×3、approval、recovery×2 |
| M4 API 与执行器 | REST 端点、DTO/错误码、SSE；调度器/Worker/租约/超时扫描/优雅停机 | 全链路 API 可用；多副本幂等通过 | api×4、executor×2 |
| M5 前端与收尾 | web 静态页、示例定义、指标、README 快速开始、端到端测试 | 免构建前端可用；E-1~E-5 全过 | web/*、main 嵌入 |

各里程碑验收：对应测试全绿 + 行数/文件数增量符合 docs/03 规划（累计越界时在当轮调整合并）。

## 3. 行数/文件数管控策略

- **按文件清单分派**：每位开发者/每次提交严格对应 docs/03 表格中的文件与目标行数，超差 ±15 行即提示精简；
- **CI 门禁**：E-1/E-2 命令进入 CI 检查，越界即构建失败（阈值精确：`(2000,2200)`、`(20,25)`）；
- **允许手段**：合并小工具函数进所属文件、抽取公共常量、减少重复错误包装；**禁止手段**：为了凑行数添加无意义空行/注释、把测试代码混入非测试文件（混入会破坏 E-1 口径，被 `*_test.go` 排除规则约束）；
- **行数统计口径**：空行与注释计入（与 `wc -l` 行为一致），规划已按该口径留余量。

## 4. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 行数/文件数越界 | E-1/E-2 失败 | 里程碑内按清单增量开发，每轮 CI 校验；越界即合并/精简 |
| 表达式引擎复杂度超预期 | 工期与行数双压力 | 内置函数先做最小集（len/contains/matches/now/addDays），表达式语法不引入第三方 DSL |
| 多副本幂等难保证 | 重复副作用 | 幂等键唯一约束 + 租约 CAS + 并发端到端测试先行（M4 内完成） |
| SQL 与内存语义漂移 | 测试盲区 | 同一测试套件双驱动运行（docs/08 §1.2） |
| 审批模式边界情况多 | 语义缺陷 | 模式判定收敛为纯函数（approval.Manager），表驱动测试覆盖全组合 |
| 前端无构建链的复杂度 | 维护成本 | 保持原生 JS + 模板渲染，不做组件化抽象；页面只读为主 |
